# Calendar Booking

Сервис бронирования встреч. Организатор создаёт встречи и настраивает доступность;
гость выбирает свободный слот и записывается.

## Люди

**Организатор**:
Человек, принимающий встречи. Владеет встречами (Meeting) и правилами доступности (Availability).
При бронировании его гостями система автоматически создаёт для гостей учётные записи.
В коде: `User`. _Avoid_: Пользователь.

**Гость**:
Человек, записывающийся на встречу. Не имеет учётной записи изначально — достаточно имени и email'а
при бронировании. При первом бронировании система создаёт для гостя учётную запись User
(по email, username — из email). Один гость может записаться на конкретную встречу только один раз.
В коде: `Guest` (вложен в Booking), `User` (после автосоздания). _Avoid_: Посетитель, клиент.

## Встречи и бронирования

**Meeting**:
Шаблон встречи, созданный организатором. Определяет: название, описание, длительность, часовой пояс,
ссылку на встречу, шаг слотов, буферы, минимальное уведомление и ограничения по времени.
Не имеет конкретной даты — это «тип» встречи (например, «Консультация 30 минут»).
Каждая встреча получает публичный UUID для внешней ссылки бронирования.

**MeetingTimeRule**:
Ограничение по времени для конкретной встречи. Например: «Консультация доступна только
по понедельникам с 14 до 17 и по средам с 17 до 19». Если правил нет — встреча доступна
в любое время, когда организатор свободен (согласно Availability).
Приоритет: MeetingTimeRule сужает окно, определённое Availability.

**Booking**:
Запись гостя на конкретный Meeting в конкретный временной слот. Содержит: гостя, дату и время,
статус (confirmed / cancelled / rescheduled). При создании система проверяет:
- Доступность организатора через Availability
- Ограничения встречи через MeetingTimeRule
- Отсутствие дубликата (тот же гость + та же встреча)

**TimeSlot**:
Свободное окно в расписании организатора, которое может стать Booking.
Вычисляется как пересечение: Availability ∩ MeetingTimeRule минус занятые слоты.

## Доступность

**Availability**:
Правила доступности организатора. Состоит из повторяющихся еженедельных правил (AvailabilityRule)
и исключений на конкретные даты (DateOverride). Принадлежит организатору.

**AvailabilityRule**:
Еженедельное окно доступности. Например: «по понедельникам с 9 до 17».

**DateOverride**:
Исключение на конкретную дату. Может сделать день недоступным или изменить рабочие часы.
Приоритет DateOverride выше, чем AvailabilityRule.

## Публичный доступ

**Public booking link**:
Каждый Meeting имеет UUID, формирующий публичную ссылку вида `/?meeting={uuid}`.
При переходе по ссылке открывается страница бронирования без необходимости авторизации —
гость видит информацию о встрече, доступные даты и слоты, заполняет данные и подтверждает.

## Основные операции

### Создание встречи (Workspace)

1. Организатор создаёт Meeting: название, описание, длительность, шаг слотов, буферы.
2. Опционально добавляет MeetingTimeRule — дни и часы, когда встреча доступна.
3. Meeting получает UUID и становится доступен для бронирования (если `isActive=true`).
4. Организатор копирует публичную ссылку и распространяет её.

### Бронирование через публичную ссылку

1. Гость переходит по `/?meeting={uuid}`.
2. Система показывает информацию о встрече и доступные даты (только те, где есть слоты).
3. Гость выбирает дату → видит доступные слоты с временем начала и конца.
4. Заполняет имя, email, заметки → нажимает Confirm.
5. Создаётся Booking со статусом `confirmed`. Гость видит подтверждение.
6. Если гость уже записан на эту встречу — система сообщает об этом.

### Бронирование через интерфейс организатора

1. Гость открывает `/` → видит профиль организатора и список встреч.
2. Выбирает встречу → видит календарь с доступными датами и слотами.
3. Заполняет данные → Confirm.

### Отмена бронирования

1. Booking переводится в статус `cancelled` (необратимо).

### Перенос бронирования

1. Исходный Booking → `rescheduled`.
2. Создаётся новый Booking со статусом `confirmed`.
